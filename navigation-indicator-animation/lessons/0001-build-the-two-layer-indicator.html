Build the two-layer navigation indicator

Cold-recall defense:
activeIndex is persistent route truth. previewIndex is temporary interaction intent. Different lifetimes require different visual layers.

Step 1 — Lift visual ownership into Navigation

A shared element cannot move between siblings if every sibling owns its own background. Start by making the parent own both indicators. Keep NavigationItem responsible for links, tooltips, and icons.

Before revealing the structure below, sketch the DOM layers on paper. Your drawing should contain one relative links wrapper, two absolute indicators, and three links above them.

Step 2 — Derive route truth instead of copying it

The active indicator is not click state. It must also be correct after a direct page load, browser Back, or a nested project URL. Derive it from the current pathname.

Route destinations: navigation.tsx:8 GitHub↗

Do not replace NavLink. The indicator needs a parent-level index, but NavLink should still provide semantic active state and aria-current="page" on the destination itself.

Step 3 — Convert indices into geometry

Each item is 36px wide and followed by 4px of spacing. Therefore, item origins are 40px apart. Keep all classes as literal strings so Tailwind can discover them during its source scan.

Give both indicators pointer-events-none absolute top-1 left-1 size-9 rounded-md. The active layer uses the active index. The preview layer uses its last preview position and changes opacity separately.

Reveal the transition classes
Checkpoint Temporarily hard-code activeIndex and previewPosition to 0, 1, and 2. Confirm exact alignment before adding interaction state. Fix geometry first; state cannot repair a 4px offset.

Step 4 — Model pointer and keyboard intent separately

Pointer hover and keyboard-visible focus can overlap, so preserve both sources. The effective preview prefers the pointer while it is inside the links and otherwise falls back to keyboard focus.

Pass an item's index-specific callbacks into NavigationItem. On pointer entry, set pointerIndex. Clear it from the links wrapper's onPointerLeave, not from every link, so moving between siblings does not create a hidden gap.

For focus, inspect event.currentTarget.matches(':focus-visible') before setting focusIndex. Clear it on blur. This prevents a pointer click—which also focuses a link—from becoming a sticky keyboard preview.

Step 5 — Make the first preview appear in place

A preview moving between already-hovered items should translate. The first preview should not fly out of its last hidden position. Separate where the layer is from whether it is visible.

When previewVisible is false, transition only opacity. When it is true, transition transform and opacity. That makes the hidden position update instantaneous while keeping visible retargeting interruptible.

Step 6 — Let CSS own interruption

Do not queue movements or calculate in-between frames in React. Each new index changes the transform target. A CSS transition begins from the currently rendered value, so rapid hover changes naturally retarget mid-flight.

Checkpoint Scrub Home → Projects → Substack faster than 150ms. The preview should change direction smoothly. If it restarts, snaps back, or finishes old movements first, search for keyframes, remounting keys, or queued state.

The project already defines the exact values. Reuse them rather than adding one-off milliseconds or curves.

Motion tokens: theme.css:114 GitHub↗

Step 7 — Fix the theme switcher's sticky click state

The theme switcher is an action, not a destination. Keep its local hover layer, but show focus styling only when focus should be visibly indicated.

Theme switcher: theme-switcher.tsx:33 GitHub↗

Do not call blur() after clicks. Removing focus disrupts keyboard and assistive-technology workflows; :focus-visible solves the visual problem without falsifying interaction state.

Step 8 — Verify the state contract

Run npm run dev, then verify behavior—not merely that the code compiles.

  1. Load / directly: Home owns the active indicator.
  2. Load /works directly: Projects owns it.
  3. Load a nested /works/... route: Projects remains active.
  4. Hover another item: active stays; preview appears at 55%.
  5. Hover the active item: a second layer does not darken it.
  6. Scrub rapidly: the preview retargets without queuing.
  7. Leave the links: the preview fades where it is; active remains.
  8. Tab and Shift+Tab: keyboard-visible previews follow focus.
  9. Click the theme switcher and move away: no style remains stuck.
  10. Hover Substack: preview appears, but it never becomes route-active.
  11. Use browser Back and Forward: route truth remains derived correctly.
  12. Enable reduced motion: state changes instantly and remains legible.

After manual behavior checks, run npm run lint and npm run typecheck. This repository has no automated UI test suite, so do not invent one inside this change.
