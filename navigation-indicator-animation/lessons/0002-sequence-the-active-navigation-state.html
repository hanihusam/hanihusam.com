Sequence the active navigation state

Make inactive icons quiet, keep hover immediate, and let route activation unfold in two readable phases: background first, icon second.

Your one win

By the end, you can implement and explain the revised Stripe-inspired sequence without timers, springs, or a second hover background.

  1. Separate inactive, interactive, and active icon meanings.
  2. Move one persistent background from route state.
  3. Delay active icon color until the background arrives.
  4. Give hover precedence so clicking never causes a dim flash.
  5. Collapse the whole sequence correctly under reduced motion.
This lesson supersedes Lesson 1. The first model kept a second background for hover preview. The revised model uses icon color for temporary intent and reserves the button background for persistent route state.

See why sequencing matters

A simultaneous state change makes the background and icon compete for the same instant. The revised interaction gives each change a job: movement first establishes the destination, then color confirms settlement.

Things to try
  1. In simultaneous mode, use “Simulate Back / Forward.” Watch both changes compete.
  2. Switch to sequenced mode and repeat. Read the phase output while the background moves.
  3. Hover an inactive item without clicking. Confirm the background stays at the active route.
  4. Click a hovered internal item. Its icon stays bright while the background catches up.
  5. Turn on reduced motion and repeat. Meaning should survive without travel or delay.
Cold-recall defense:
Hover is immediate icon feedback. Active route is a sequenced background and icon state. Hover wins because replaying the active delay would make a clicked icon flash dim.

Step 1 — Give icon colors distinct meanings

Start in NavigationItem. Remove the item-owned background span. The shared active background will move into the parent later.

Wrap the icon in a span whose default color is --icon-secondary. Hover, keyboard-visible focus, and active route all target --icon-primary, but only active route receives a delay.

Current item background: navigation-item.tsx:30 GitHub↗

Checkpoint Before adding active motion, verify that every icon is dim at rest and that hover changes only icon color over 150ms. If any background appears, the old item-local layer is still present.

Step 2 — Derive the active route in Navigation

A click is not the source of truth. Direct loads and browser history must place the background correctly, so derive the active index from React Router's pathname.

Keep NavLink. The parent needs an index for geometry, while each link still needs semantic aria-current="page" for assistive technology and its active icon selector.

Step 3 — Add one shared active background

Wrap only the three destinations in a relative flex container. Render the background before the links so their icons remain above it. The theme switcher stays outside this route-owned layer.

Navigation composition: navigation.tsx:27 GitHub↗

Step 4 — Delay only unhovered active color

The background uses --duration-base, or 200ms. Give the new active icon the same transition delay, then let its existing 150ms color transition begin.

The delay must apply only when the active link is neither hovered nor keyboard-focus-visible. That condition encodes “hover wins” directly and avoids JavaScript timers.

Why no timer?
The sequence is a relationship between CSS transitions. Using the same --duration-base token for background duration and icon delay keeps them synchronized, and reduced motion can zero both automatically.

Step 5 — Reason through hover precedence

Trace these cases before opening the browser:

Event Background Icon
Hover inactive item Stays at active route Brightens immediately
Click hovered item Moves over 200ms Remains bright from hover
Back / Forward Moves over 200ms Brightens after 200ms
Pointer leaves clicked item Continues or stays active Remains bright from active state
Checkpoint Click Projects while hovering it, then move the pointer away before 200ms. The icon must never flash dim. Next use Back without hovering Home; that is where the delayed icon phase should be visible.

Step 6 — Keep the theme action separate

The theme switcher is not a route and never receives the shared active background. Its local hover treatment may remain, but pointer-created focus must not leave that background looking selected.

Step 7 — Let reduced motion collapse the sequence

The project already sets --duration-fast and --duration-base to zero under prefers-reduced-motion: reduce. Because both background duration and icon delay use those tokens, route state becomes immediate without losing any colors or backgrounds.

Step 8 — Verify behavior, not just appearance

  1. Load /: Home background and icon are active immediately.
  2. Load /works or /works/...: Projects is active without an entrance animation.
  3. Hover an inactive item: only its icon changes color.
  4. Leave it: the icon returns to the dim token over 150ms.
  5. Click it while hovered: the icon never flashes dim.
  6. Use Back and Forward without hovering: background moves first, then icon color begins.
  7. Hover Substack: its icon brightens, but no active background moves.
  8. Tab through links: focus-visible produces the same icon-only feedback.
  9. Click the theme switcher and leave: no focused background remains stuck.
  10. Enable reduced motion: route state changes immediately with no delay.
  11. Check both themes for sufficient inactive-icon contrast.
