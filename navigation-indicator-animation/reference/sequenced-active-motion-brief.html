Sequenced active navigation motion

The confirmed state, timing, and precedence rules for the revised navigation. This supersedes the earlier two-background motion brief.

Visual states

State Icon Background
Inactive --icon-secondary None
Hover or focus-visible --icon-primary Unchanged
Active and settled --icon-primary --nav-item-surface-active

Route-change sequence

  1. The old active icon begins returning to --icon-secondary unless interaction still brightens it.
  2. The shared active background translates to the new route over 200ms.
  3. After a 200ms delay, the new active icon transitions to --icon-primary over 150ms.
Property Curve Duration Delay
Background transform --ease-in-out-quart --duration-base · 200ms 0ms
Icon color --ease-hover --duration-fast · 150ms --duration-base · 200ms when active only

Precedence rules

  • Hover and keyboard-visible focus have no delay and affect icon color only.
  • Hover wins over the active delay. A bright hovered icon never dims merely to replay the active sequence.
  • The active delay is visible during Back, Forward, or other route changes when the destination icon is not already interactive.
  • Substack is external and never receives the active background.
  • The theme switcher remains an action with its own hover and :focus-visible feedback.

Reduced motion

The existing reduced-motion rule changes both duration tokens to 0ms. The background jumps to its route, the active icon changes immediately, and all state distinctions remain.

Cold-recall defense:
Hover answers “where might I go?” using icon color only. Active route answers “where am I?” using a persistent background followed by icon color. Hover has precedence so the sequence never introduces a flash.
